# React Native Template

Expo + TypeScript template with session auth, file-based routing, Unistyles, and
TanStack Query.

It pairs with [`backend-template`](https://github.com/andradeecom/backend-template).
The session id lives in the OS keystore rather than AsyncStorage — see
[docs/authentication.md](docs/authentication.md).

## Requirements

- Node `24.x` (see `.nvmrc`)
- pnpm `11.21.0` (pinned via `packageManager`)
- Xcode (iOS) and/or Android Studio for native builds
- A running instance of the backend API

## Getting started

```bash
pnpm install
cp .env.example .env.local   # then fill in the blanks
pnpm ios                     # or: pnpm android
```

`ios/` and `android/` are generated by `expo prebuild` and are **not** committed —
`app.json` is the source of truth for native config. Run `pnpm prebuild` to
regenerate them after changing native settings.

> The API base URL is `http://localhost:3001/api` in `src/lib/api-client.ts`. A
> physical device cannot reach your machine's `localhost`; point it at your LAN
> IP or a tunnel.

## Authentication

Auth is an **opaque server-side session**, not a JWT. The session id lives in the
OS keystore via SecureStore — Keychain on iOS, Keystore-backed storage on
Android — never AsyncStorage, which is unencrypted. It is attached explicitly as
a header rather than relying on the ambient cookie jar.

Full detail — storage scoping, rotation capture, logout ordering, and CSRF — in
[docs/authentication.md](docs/authentication.md).

## Routing

Expo Router, file-based from `src/app/`. Unauthenticated screens live in the
`(auth)` group, which does not appear in the URL — they resolve as `/login`,
`/register`, and so on.

```
src/app/
├── (auth)/         login, register, forgot-password, reset-password, verify-email
├── (tabs)/         index, profile
├── auth/[...slug]  deep-link shim for emailed tokens
├── change-password modal on the root stack
└── _layout.tsx
```

Emailed links point at `/auth/verify-email?token=…`, a path shared with the web
client that does not match the app's own route. `src/app/auth/[...slug].tsx`
bridges the two by whitelisting known auth paths and redirecting, forwarding the
token. Keep that whitelist in sync when adding auth routes.

## Styling

`src/theme/config.ts` defines the whole design system and is imported once at
startup from `src/index.ts` — its side effect of calling `StyleSheet.configure`
is the point. It registers a light/dark theme pair built from the shared tokens
alongside it (`colors`, `font`, `spacing`, `radius`, `shadows`, `z-index`,
`opacity`).

Style with `StyleSheet.create((theme) => ({...}))` from `react-native-unistyles`,
never React Native's own `StyleSheet`, and pull values off `theme`
(`theme.spacing[4]`) rather than hardcoding them.

Components follow atomic design: `atoms/` → `molecules/` → `organisms/`. Auth
organisms own their form and take plain callbacks as props; the screen owns the
mutation and navigation.

## Releasing

The **Bump Version** GitHub Action (`workflow_dispatch`) bumps `package.json`,
syncs `app.json`'s `expo.version`, then commits, tags, and pushes. Dispatch it
from `main` — it has no branch filter, so it tags whichever branch you run it
against.

## Contributing

`main` is protected by a branch ruleset: it cannot be force-pushed or deleted,
and changes land through a pull request. Only the **admin** repository role can
bypass that — for everyone else the requirement is absolute, with no bypass
option offered. Owners listed in `.github/CODEOWNERS` are auto-requested for
review on every PR.

```bash
git switch -c feat/short-description
# ...work...
git push -u origin feat/short-description
gh pr create --fill
```

**Branch names** carry the same prefix as the commit type: `feat/`, `fix/`,
`docs/`, `refactor/`, `chore/`.

**Commits** follow [Conventional Commits](https://www.conventionalcommits.org):

```
<type>(<optional scope>): <summary in the imperative mood>

<body explaining *why*, not what the diff already shows>
```

Types: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `ci`, `perf`.
Append `!` and add a `BREAKING CHANGE:` footer when the change breaks callers —
for example `refactor(auth)!: issue sessions instead of JWTs`.

Split work into commits that each stand on their own rather than one large
commit at the end. Husky runs Prettier and ESLint on staged files, so a commit
that fails linting will not complete.

**Before opening a PR**, run the checks below locally; describe *why* the change
is needed and call out anything that alters behaviour for existing clients.

```bash
pnpm lint
pnpm typecheck
```
